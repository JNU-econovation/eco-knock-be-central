### 판정이 갈린 지점

- **wallet-tx (new 3승):** old는 3회 모두 요청과 무관한 기존 회원 일괄 지갑 생성 메서드의 트랜잭션 전파 속성까지 바꿨고, new는 필요한 리스너만 고쳤다. 다만 원본 커밋도 이 메서드를 같이 바꿨기 때문에, old의 선택을 "틀렸다"고 보기는 어렵다.
- **airquality-lazy-init (3무, 판정이 순서에 따라 엇갈림):** old는 3회 모두 동시 첫 요청의 unique 제약 충돌을 막는 native upsert(`ON CONFLICT`)를 추가했고, new는 원본 커밋처럼 단순한 "조회 후 없으면 생성"으로 구현했다. 심판은 old의 정확성을, new의 최소성과 컨벤션을 높게 쳤다. new의 정확성이 4점으로 깎인 원인이 이것이다. new의 verifier도 이 경쟁 상태를 비차단 위험으로 보고했다.
- **wallet-tx/old/rep3 회귀 14건:** 그룹 통합 테스트에서 `MemberWalletService` 빈을 찾지 못해 14개가 모두 실패했다(재현 확인). 인수 테스트, 감사, 블라인드 비교는 모두 이 문제를 놓쳤고, 전체 회귀 검사만 잡아냈다. 회귀 검사를 품질 지표에서 빼면 안 되는 이유다.

## 3. 이 결과로 말할 수 있는 것과 없는 것

말할 수 있는 것
- developer 에이전트를 없애고 오케스트레이터가 직접 구현하게 하면, 이 레포의 일반적인 기능·리팩터링 작업에서 품질 저하 없이 비용·토큰·시간이 크게 준다.
- 작업이 어렵고 맥락이 많이 필요할수록 절감 폭이 커진다.

말할 수 없는 것
- **기각 규칙의 효과.** 30회 동안 blocking 지적이 한 번도 나오지 않아서 기각할 기회가 없었다. "기각 언급" 2건은 둘 다 "기각한 지적도 없습니다"라는 문장이었다.
- **리팩터 루프에서의 차이.** 루프가 한 번도 돌지 않았다. verifier가 지적을 많이 하는 작업에서는 차이가 더 커질 수도, 작아질 수도 있다.
- **다른 설정에서의 크기.** effort medium 기준이다. high나 max에서는 절대값이 달라질 수 있다.

## 4. 한계

- 작업당 3회라 표본이 작다. 다만 비용은 다섯 작업 모두 old의 최솟값보다 new의 최댓값이 낮아 범위가 전혀 겹치지 않고, 소요 시간도 `restclient-builder`를 뺀 네 작업에서 겹치지 않는다.
- 인수 테스트는 Claude가 원본 커밋과 요구사항만 보고, 에이전트 결과를 보기 전에 작성해서 고정했다. 그래도 같은 계열 모델이 쓴 테스트라는 한계는 있다.
- 감사와 심판은 Claude가 아닌 Codex 모델로 자기 편향을 줄였지만, LLM 판정이다.
- 비용은 Claude Code가 보고한 정가 기준 추정치이고, 구독 플랜의 실제 청구액이 아니다.
- 대형 작업(`airquality-aggregate`, 원본 580줄)은 비용 때문에 제외했다.

## 5. 측정 방법

### 작업 재현

각 run은 다음 순서로 진행했다.

1. 원본 기능 커밋의 부모 시점에 git worktree를 만든다.
2. 하네스 파일(`AI.md`, `CLAUDE.md`, `AGENTS.md`, `skills/`)만 변형의 커밋(`09b1731^` 또는 `2ff505b`) 것으로 덮어쓴다.
3. 원본 커밋의 요구사항을 프롬프트로 주고 headless로 실행한다.

   ```
   claude -p --output-format stream-json --verbose --forward-subagent-text \
     --setting-sources project,local --permission-mode bypassPermissions \
     --model claude-opus-5-5
   ```

4. 비용·토큰·시간은 stream 로그의 최종 결과에서, 서브에이전트의 도구 호출과 테스트 실행 횟수는 서브에이전트 세션 기록까지 합산해서 집계한다.

사용량 한도에 걸린 run은 결과를 남기지 않고 같은 run을 다시 실행했다.
